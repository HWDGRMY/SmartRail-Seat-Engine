# 测试规范（Standardized Verification Specification）

> 这份文档定义**怎么证明出票结果是对的**。它不是"再写几个测试用例"，
> 而是把"合不合理"变成机器可判定的条款，再用同一套条款去核验所有版本。

## 1. 为什么需要它

项目原有 700+ 条断言，全部是**期望式**的："我期望 A，看是否得到 A"。
它们能守住已知行为，但守不住**涌现出来的不合理结果** ——
因为没人预先写下"这里不该这样"。

建立这套规范的过程本身立刻抓到 5 个真缺陷（见 §5），
其中 3 个是既有 152 条断言**完全无法发现**的：

* V2 在空车上把 4 人全部候补，却报 `OPTIMAL`；
* V2 的"商务座"订单发出**一等座**；
* V1/V2 在有余票时把人放进候补。

**结论：期望式断言与不变量核验是互补的两半，缺一不可。**

## 2. 三层结构

```
smartrail/validation.py          规范定义 + 核验器（判据，与被测对象解耦）
tools/verify_conformance.py      执行器：场景矩阵 + 随机模糊 + 版本对照
tools/capture_v2_defect.py       V2 缺陷取证（可复现的现场）
tests/test_conformance.py        把规范接进 pytest，守住回归
docs/TEST_SPEC.md                本文档
```

关键设计：**规范只描述"结果必须满足什么"，不关心谁产出的。**
因此 V1 / V2 / V3 共用同一套判据，版本之间的差异会被直接暴露。

## 3. 不变量清单（18 条）

### RESOURCE 资源一致性（8 条）

| 编号 | 条款 |
| :--- | :--- |
| R1 | 一个座位不能卖给两个人 |
| R2 | 一个人最多一个座位 |
| R3 | 座位必须真实存在 |
| R4 | 已占用的座位不得再分配 |
| R5 | 轮椅停放位不得重复分配 |
| R6 | 停放位有余时轮椅旅客不得坐普通座位 |
| R7 | 普通旅客不得占用轮椅停放位 |
| R8 | 席别必须符合订单要求 |

### COMPLETENESS 出票完整性（3 条）

| 编号 | 条款 |
| :--- | :--- |
| C1 | **有空座时不得候补** —— "出票优先"的机器判据 |
| C2 | 候补与已分配不得重叠 |
| C3 | 不得凭空少人 |

### SAFETY 安全底线（3 条）

| 编号 | 条款 |
| :--- | :--- |
| S1 | 硬绑定配对必须同车厢（Tier 0） |
| S2 | 需照护者必须与照护人同车厢 |
| S3 | 同一订单不得跨车厢 |

### CONSISTENCY 自洽性（4 条）

| 编号 | 条款 |
| :--- | :--- |
| K1 | 报告亲和度必须可复算（**选入**） |
| K2 | Tier 0 计数必须与逐条复算一致（**选入**） |
| K3 | 出票人数必须与座位数一致 |
| K4 | 不得声称最优却什么都没做 |

**K1/K2 为什么是"选入"**：它们要求"用与求解器**完全一致**的 Scorer 配置
复算"。各版本内部构造 Scorer 的参数并不相同（例如是否带 `bay_slot_ids`），
拿近似配置去复算会把"配置差异"误报成"亲和度不可复算" ——
实测 v1 被误报 K1，差值恰好 −200080（≈ 两条无障碍类惩罚），
而那条路径的放置本身合法。**判据不能依赖"我猜的配置"。**

## 4. 怎么跑

```bash
python tools/verify_conformance.py                  # 场景矩阵 + 120 轮模糊 + 版本对照
python tools/verify_conformance.py --quick          # 30 轮模糊，迭代用
python tools/verify_conformance.py --scenario 轮椅   # 只跑名字含关键词的场景
python tools/verify_conformance.py --json out.json  # 落详细结果
python tools/verify_conformance.py --versions v1,v2
python tools/capture_v2_defect.py                   # V2 缺陷取证
python tests/pytest_shim.py -q                      # 全量期望式断言
```

模糊测试用**固定种子**（`20261009` / 占用用 `20261019`），失败可复现。

## 5. 已抓到的真缺陷

| # | 缺陷 | 抓它的条款 | 状态 |
| :--- | :--- | :--- | :--- |
| 1 | V2 空车上 4 人全部候补，却报 `OPTIMAL` | C1, K4 | 已修（Scorer 配置 + 候选池索引错位修好后 CP-SAT 自愈） |
| 2 | V2 的"商务座"订单发出一等座 | R8 | 已修 |
| 3 | V2 报告亲和度与独立复算差 −100040（Scorer 漏带停放位信息） | K1 | 已修 |
| 4 | 余票不足全员时整单拒票，本可部分出票 | C1 | 已修（`blocking` → `advisory`） |
| 5 | 轮椅旅客有空余停放位却坐普通座位 | R6 | **待修** |
| 6 | 普通旅客占用轮椅停放位 | R7 | **待修** |
| 7 | 部分出票时有人无座也无候补记录 | S2 | **待查** |

### 5.1 缺陷 1 的根因（已定位并修复）

三个问题叠加，任何一处单独存在都不足以解释全部现象：

1. **评价用的 Scorer 漏带停放位信息** —— V1 的两处 `Scorer(...)` 都传了
   `accessible_available` / `wheelchair_bays_free` / `bay_slot_ids`，
   V2 是裸的 `Scorer(config)`。后果：把"坐在停放位上"误判成
   "轮椅旅客拿到普通座位"，**凭空产生 Tier 0**，报告亲和度比复算高 100040。
2. **候选池与求解器用了两份不同的座位列表** —— `build_candidates` 按席别
   过滤了列表，而 `solve_cpsat` 用**未过滤**的列表按索引取座位，
   索引整体错位，于是"商务座"订单发出一等座。
3. **同车厢约束的写法把"谁都不坐"纳入了合法解空间** —— 逐车厢双向蕴含
   在两人都不落座时平凡成立，而"都不坐"恰好是唯一能绕开全部约束的解。

修复后 CP-SAT 自己就能坐满 4 人，病态解守卫不再是主要路径（保留作兜底）。

### 5.2 仍未消除的（缺陷 5–7）

```
四位轮椅 -> 04车01A, 04车01B, 04车01C, 04车01D
停放位落点: 04车01A, 04车01B（12车01A/B 空着）
```

轮椅旅客拿到了 `01C/01D`（普通座位），而两个停放位空着 ——
违反需求"无障碍要求完全独立编号，不占座位票额"的本意。
`fuzz#5` 里还出现普通旅客占用停放位（R7）。

这两条都在**轮椅与停放位的交互**上，需要专门排查
`_compose_fallback_combos` 与候选池对停放位组合的覆盖。

## 6. 尚未决断的产品问题

**"同车厢"约束遇到碎片化余票时，应当拆单出票还是拒票？**

实测：该席别剩 4 个空座、下 3 人单（3 位成人，同属一个出行单元），
V1 给出 **0 出票、3 人全部候补** —— 因为强制"同一单元必须同车厢"，
而全列没有任何一节车厢还有 3 个连着的空位。

* 若坚持"同车厢"为硬约束 → 当前行为正确，但**有空座仍拒票**与
  "以出票为目的"的底线冲突，应当给出明确提示而不是静默候补；
* 若允许跨车厢拆单 → 需要修改 S3 的等级，并在界面上如实告知。

**这条需要产品决策，不应由实现方单方面选择。** 规范先把事实固定下来，
无论选哪边，都能用同一套条款回归。

## 7. 维护约定

1. **新增"必须满足"的约束时，先在 `INVARIANTS` 里登记条款**，再写实现。
2. 条款的 `severity` 只有四档，`RESOURCE`/`COMPLETENESS`/`SAFETY` 属事故。
3. 核验器**不得依赖被测方的内部配置**（见 K1 的教训）。
4. 场景矩阵要覆盖四个维度：人数 × 人群构成 × 席别 × 余票状态，
   再加上特殊资源（轮椅停放位）。
5. 模糊测试的种子写死；发现失败先固定种子复现，再改代码。
